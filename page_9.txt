User > React frontend > Supabase Auth > authenticated API request > FastAPI > matching engine > PostGIS/PostgreSQL
 > OSRM routing (or approximate fallback) > ranked proposals with explanations > JSON response > frontend
Candidate details exposed to the client omit contact and auth data. Proposals are computed on demand and are not persisted.
Figure 3. System architecture and primary data flow.
The frontend never decides feasibility: the backend is authoritative. The routing module sits behind a provider
interface, so OSRM, OpenRouteService or the fallback can be swapped without changing the matching logic.
Proposals are recomputed on each request, so cancelling or expiring a request removes it from later results
without extra bookkeeping.
